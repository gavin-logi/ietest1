## 遇到的问题与解决办法

### 1. 宿主机端口被同机另一个项目占用
- 现象：`docker compose up` 报 `Bind for 127.0.0.1:5432 failed: port is already allocated`。
- 原因：同机运行着 barebone 模板项目的容器，占用 5432、8000、8090、9000、9001。模板把宿主机端口写死。
- 解决：
  1. 模板改进：`docker-compose.yml` 的宿主机端口改为 `${POSTGRES_HOST_PORT:-5432}` 等（默认值不变），`.env.example` 增加对应可选项；`vite.config.js` 的 /api 代理端口读取 `BACKEND_PORT`。以后同机多项目只改 `.env`。
  2. 本次验证经用户同意，用 `docker stop` 暂停 barebone 的 5 个容器（不删除、不丢数据），验证完成后再 `docker start` 恢复。
- 教训：不要擅自停止他人的容器；修改 `.env` 受权限规则限制，AI 无法改，需用户自己改或授权。

### 2. 本机连接 postgres 被拒绝（容器 healthy，端口转发丢失）
- 现象：`migrate` 报 `connection to server at "127.0.0.1", port 5432 failed: Connection refused`，但容器内 `pg_isready` 正常。
- 原因：本机使用 Colima，端口经 ssh 转发；停止、启动其它容器后，5432 的转发没有重新建立（`lsof -iTCP:5432` 无监听）。
- 解决：`docker restart` 无效；`docker compose up -d --force-recreate postgres`（数据卷保留）后转发恢复。
- 排查提示：先 `lsof -nP -iTCP:<端口> -sTCP:LISTEN` 确认宿主机是否真的在监听，再判断是应用问题还是转发问题。

### 3. 无法在 Apple Silicon 上构建 linux/amd64 镜像
- 现象：`docker build --platform linux/amd64 .` 报 `image ... was found but does not provide the specified platform (linux/amd64)`；`DOCKER_BUILDKIT=1` 报 buildx 组件缺失。
- 原因：Colima 的 docker 没有 buildx 插件，只能用经典构建器，它在 arm 守护进程上跨平台构建 COPY 步骤会失败；`--no-cache` 与预先拉取 amd64 基础镜像都无效。amd64 容器本身可运行（QEMU 已就绪）。
- 处理：未强行修复。ECS 模拟改用 arm64 构建的同一 Dockerfile 镜像。正式推送 ECR 前，需安装 buildx（`brew install docker-buildx`）或在 CI（amd64 runner）构建，并在 amd64 上再验证一次。
- 副作用：为排查拉取过 amd64 基础镜像，已重新拉取 arm64 版本恢复本地标签。

### 4. 命令编写失误（非项目问题）
- 把 `docker run` 参数放进一个字符串变量再展开，参数被当成一个整体，报 `unknown flag`。改用 bash 数组 `"${A[@]}"` 传参。
